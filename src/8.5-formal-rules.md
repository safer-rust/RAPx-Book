# Chapter 8.5. Formal Reasoning Rules

The verifier discharges each safety property by symbolic reasoning over the VM state. This chapter first describes the symbolic VM state (§8.5.1), then the deduction rules that read that state (§8.5.2), and finally the special treatment of `Alias`, which is a hazard by default but also expresses a no-aliasing precondition (§8.5.3).

## 8.5.1 The Symbolic VM

### VM design

The `SymbolicVm` ([`vm/mod.rs`](https://github.com/safer-rust/RAPx/blob/main/rapx/src/verify/vm/mod.rs)) is a *semantic* MIR executor that replaces the earlier pattern-matching forward verifier. Rather than deriving ad-hoc facts from MIR patterns, it executes the MIR items the backward slicer retained (§8.4.2) and directly builds a symbolic state (`VmState`) with a Z3 term for every value.

The VM is stateless: `run(ctx, tcx, goal)` is a pure `input → state` mapping over a `ProofGoal` ([`slicer/types.rs`](https://github.com/safer-rust/RAPx/blob/main/rapx/src/verify/slicer/types.rs)) — the path plus its retained `RelevantItem`s (statements, terminators, inlined `CalleeEntry`/`CalleeExit` markers, injected `ContractFact`s, and `Forget` loss-of-precision markers). The Z3 context is borrowed rather than owned, so a single context is reused across property checks.

Execution proceeds in three steps: bind the function parameters as fresh symbolic values, walk the retained items in forward path order — each MIR statement or terminator is a *transfer function* that updates `VmState` — and finally propagate the accumulated state to the checkpoint. By the time execution reaches a checkpoint, the state reflects exactly the branch conditions and memory effects of that path.

```text
   ProofGoal { path, items: Vec<RelevantItem>, block_fn }
   (produced by the backward slicer, §8.4.2)
                    │
                    ▼
   SymbolicVm::run(ctx, tcx, goal)        ← stateless, pure input → state
                    │
                    ▼
   VmState::new(...)                      ← empty state (structure below)
                    │
                    ▼
   execute_items(&items)                  ← forward path order
                    │
                    ├─ init_parameters():  _1.._N ← fresh Z3 constants
                    │
                    └─ for item in items:
                          Statement    → exec_statement
                          Terminator   → exec_terminator
                          CalleeEntry  → handle_callee_entry  (save_frame)
                          CalleeExit   → handle_callee_exit   (restore_frame)
                          ContractFact → assert_contract_fact
                          Forget       → (no-op)
                    │
                    ▼
   propagate_from_checkpoint(block, path_blocks)   ← back-fill omitted provenance chains
                    │
                    ▼
   VmState ──► PropertyChecker::check ──► Z3 (assert_all + negation-as-failure)
```

The state is deliberately layered so that inlining swaps out only the frame-scoped part:

- **Frame-scoped** (`FrameState`): the current function's identity and its MIR-local bindings (`values`, `slots`, `local_fields`, plus `move_sources`/`op_sources` bookkeeping). Entering an inlined callee saves this layer and restores it on exit, so the callee reuses MIR locals freely.
- **Path-scoped** (`Memory` + `Constraints`): the object space — allocations, per-byte state, per-allocation fields — and the accumulated solver assertions and term caches. These persist across inlined frames: memory and path conditions are shared by caller and callee.
- **Scratch** (`InlineCtx` + `PathFacts`): the recursive-inline depth and per-call bindings, and the per-path facts latched while stepping.

```text
VmState
 ├─ ctx: &Context, tcx: TyCtxt         ← shared handles (borrowed Z3 context, reused across checks)
 │
 ├─ current_frame: FrameState          ← frame-scoped (saved/restored on inline entry/exit)
 │    values, slots, local_fields, move_sources, op_sources
 ├─ caller_frames: Vec<FrameState>     ← saved caller frames (path-replay inlining)
 │
 ├─ memory: Memory                     ← path-scoped (accumulates across inline)
 │    allocations: Vec<Allocation>
 │    bytes:  (AllocId, offset)       → ByteInfo { value, init, nul }
 │    fields: (AllocId, view_ty, [i]) → VmValue
 │
 ├─ constraints: Constraints           ← path-scoped
 │    assertions:  Vec<Bool>           ← branch/guard + contract + layout facts
 │    term_caches: TermCaches          ← sizes / aligns / not_mask_terms /
 │                                       exact_div_roots / div_roots / iter_ptr_offset
 │
 ├─ inline: InlineCtx                  ← recursive-inline scratch state
 │    inline_depth, arg_referents, deferred_field_writes
 │
 └─ path_facts: PathFacts              ← per-path facts
      reenter / split_transmute_asserted / alias_hazard_accepted /
      has_checked_bounds / saw_next_discriminant
```

The deduction rules in §8.5.2 read three things out of this state — values, allocations, and provenance — described in the subsections below.

### Values and invariants

Every MIR local maps to a symbolic value (`VmValue`):

```text
VmValue { term, ty, provenance, invariants, field_offset, discriminant, bool_cond }
```

- `term` — a Z3 term. For pointer/reference types (`&T`, `*const T`, `Box<T>`, …) it is the address; for scalar types it is the value; for aggregate types it is the base address of the stack slot backing the aggregate.
- `ty` — the Rust type, for layout queries.
- `provenance` — `Option<Provenance>` (see below); `None` for a scalar.
- `invariants` — the derived invariants (`ValueInvariants`): `non_null: bool`, `init: bool`, `in_bounds: bool`, and `align_n: Option<Int>` — a Z3 term `n` with `term % n == 0`, carried for a concrete alignment *and* for a generic type's symbolic `align_T`. These are the "fast-path flags" of §8.5.2.
- `field_offset` — this scalar is a compile-time `offset_of!` field offset, propagated to a pointer's provenance when used as an `add`/`byte_add` offset (origin information, not an SMT-assertable invariant).
- `discriminant` — a symbolic enum variant index (e.g. `Iterator::next` returns `Some(x)` iff `!is_empty`), tying `switchInt` branches to the real condition instead of a fresh symbol.
- `bool_cond` — the direct boolean condition of a comparison result (`Le/Lt/Ge/Gt/Eq/Ne`), so `switchInt`/`Assert` emit a precise path condition (`offset <= len`) instead of `ite(cond, 1, 0) != 0`.

### Field values

An aggregate's fields are tracked separately from the whole local, as a map from
a *(local, field-index path)* — or *(allocation, viewed type, field-index path)*
— to a `VmValue`:

```text
local_fields[(local, [i₀, i₁, …])]        = VmValue     (FrameState)
fields[(alloc_id, view_ty, [i₀, …])]      = VmValue     (Memory)
```

- `FrameState::local_fields` keys a field by its *local* and a projection path (`p.0.1`).
  It is what a `(*p).field` read resolves through for a struct/tuple carried by
  a MIR local — the *binding-value* layer.
- `Memory::fields` keys a field by its *allocation* and the ADT it is viewed
  as (`view_ty`), so a `&*NonNull<ADT>` dereference resolves the pointee's fields
  (`(*leaf).len`) regardless of which local holds the pointer; the viewed type
  disambiguates reinterprets of one allocation under different ADTs (e.g.
  `LeafNode` vs `InternalNode`) — the *memory-contents* layer.

A pointer field's pointee is *not* a field entry of its own — it is an
allocation reached through that field value's `provenance` (`alloc_id` +
`offset`), recorded in the allocation table below.

### Provenance

Every pointer value carries the allocation it points into, the byte offset within it, and (when known) the structure of that offset:

```text
provenance(p) = { alloc_id: a, offset: off, offset_kind: k }   ⇔   p points into allocation a at byte offset off
```

`offset_kind` classifies the offset so the checker can use a cheaper, more precise proof: `Field` carries the "field in-bounds" guarantee (`offset + size_of(field) <= size_of(container)`, e.g. `Option::as_slice`); `Element(i)` tracks the element index so `InBound` checks `i + count <= slice_len` linearly instead of the non-linear byte form `(i+count)·S <= len·S` (undecidable in Z3 NIA for a generic `S`); `Byte` marks a byte-strided (`byte_add`) or unclassifiable offset. `offset_kind` is `None` at the base (`offset == 0`).

A cast (`&mut → *mut`, `*mut → *const`) preserves provenance; a plain copy `q = p` copies provenance (so `p` and `q` are aliases).

### Allocation table

Every allocation `a` the VM tracks is one entry in an allocation table (`vm::state::Allocation`). Its shape is encoded by an explicit kind enum rather than by which `Option` fields happen to be set:

```rust
enum AllocKind {
    Object,            // a single object (Box<T>, struct, scalar, or untyped raw buffer)
    Slice { len: Int }, // a slice/array buffer with a known element count
    External,          // an external raw-pointer parameter (unknown size/nullability)
}

enum Liveness {
    Unassumed,          // no assumption (external allocations then fail Alive)
    AssumedFor(Region), // named region: an Alive(p, 'a) contract/invariant, or
                        // 'static for ValidCStr / Allocated params / 'static data
}

struct Allocation {
    // shape — always present (Z3 terms, may be symbolic)
    base:  Int,   // base address: a fresh Z3 constant
    size:  Int,   // byte size
    align: Int,   // alignment

    kind:       AllocKind,        // object vs slice vs external

    // type facts — what the allocation stores, and (for a pointer container)
    // what the stored pointers target
    element_ty: ContentTy,      // Typed(T) for a known type; Generic for a symbolic T
    for_each:   ForEachFacts,   // uniform facts about every element pointer,
                                // established by `x.iter()` for_each invariants:
                                //   target_ty:  Option<Ty>       — Typed(iter(), T)
                                //   aligned_ty: Option<Ty>       — Align(iter(), T)
                                //   allocated:  Option<(Ty, Int)> — Allocated(iter(), T, n)
                                //   owning:     bool             — Owning(iter())

    // edges — Option
    parent:     Option<AllocId>,  // source allocation of a sub-view (s[i..j]/get,
                                  // split_at/align_to/as_chunks, from_raw_parts);
                                  // root_alloc follows this edge to group aliases
    slice_data: Option<AllocId>,  // data allocation of a two-part value (Vec/String/
                                  // CString's heap buffer, or a &[T]'s slice contents)

    // flags — default false
    dead:          bool,  // freed (StorageDead / Drop)
    initialized:   bool,  // contents hold an initialized (readable) value (Box::new/Vec/
                          // &T referent/callee return/write/ValidCStr/const data);
                          // false for new_uninit/uninit
    liveness:      Liveness,  // Unassumed | AssumedFor('a): how liveness is
                              // established and for which region (external allocations
                              // only — their memory is owned by the caller)
    nul_terminated: bool, // valid C string (from ValidCStr)
}
```

The entry differs by how the allocation was created:

| creation | kind | element_ty | slice_data | parent |
|---|---|---|---|---|
| `Box::new(v)` — heap object | `Object` | `Typed(T)` | — | — |
| `Vec`'s heap buffer | `Slice { len }` | `Typed(T)` | — | — |
| `&[T]` reference's stack slot | `Object` | `Typed(T)` | `Some(data)` | — |
| `split_at` half / `from_raw_parts` view | `Slice { mid }` | `Typed(T)` | — | `Some(src)` |
| external `*mut T` parameter | `External` | `Typed(T)` | — | — |

- `base`/`size`/`align` — base address, byte size, and alignment. `size` and `align` may be symbolic for a generic element type; for an external parameter they are unknown (the allocation is sized as "unbounded").
- `kind` — the allocation shape. For `Slice { len }`, `size` is derived as `len · size_of(element_ty)`.
- `element_ty` — the content type used by `Typed` and bounds checks. `ContentTy::Typed(T)` carries the concrete element/object type (or `u8` for a raw byte buffer); `ContentTy::Generic` marks a symbolic element type whose concrete `Ty` cannot be determined (e.g. `from_raw_parts::<T>`, sized by the shared symbolic `sizeof_T`).
- `for_each` — uniform facts about every element pointer of a container, established by `x.iter()` for_each invariants: `target_ty` (`Typed(iter(), T)`), `aligned_ty` (`Align(iter(), T)`), `allocated` (`Allocated(iter(), T, n)`), and `owning` (`Owning(iter())`). Anchored to the container's allocation so a pointer loaded from it resolves the fact via its provenance.
- `parent` — the allocation a sub-view was derived from (`s[i..j]` / `s.get(range)`, `split_at` / `align_to` / `as_chunks`, `from_raw_parts`); `⊥` for a fresh `Box`/`Vec` allocation. `root_alloc` follows this edge to group aliasing views.
- `slice_data` — the data allocation of a two-part value: a `Vec`/`String`/`CString` heap buffer, or a `&[T]`'s slice contents. It is linked from the *header* allocation (the one the value's provenance names), and followed by `as_ptr()`/`into_boxed_slice`/`drop`/mutation.

### Provenance recording rules

The VM maintains provenance in execution order, one transfer per MIR statement/terminator (`slice_len` below denotes `AllocKind::Slice { len }`, read via `Allocation::slice_len()`):

```text
── Allocation creation (Box::new / Vec::new / …) ──
a := fresh
──────────────────────────────────────────
prov(p) = (a, 0)      a.parent = ⊥         (a.kind = Slice { len } for a Vec/slice)

── View of a pointer (&*p / &mut *p / as_ptr / as_mut_ptr / into_raw) ──
prov(p) = (a, off)
────────────────────────
prov(&*p) = prov(p) = (a, off)          (the view inherits p's provenance)

── Slice view (from_raw_parts(ptr, n)) ──
prov(ptr) = (a, off)
────────────────────────────────────────
b := fresh   prov(s) = (b, 0)   b.kind = Slice { len: n }   b.parent = a

── Split (split_at(s, mid)) ──
prov(s) = (a, 0)   a.kind = Slice { len }   0 ≤ mid ≤ len
──────────────────────────────────────────────────────────────
prov(s[..mid]) = (b₁, 0)   b₁.kind = Slice { len: mid }      b₁.parent = a
prov(s[mid..]) = (b₂, 0)   b₂.kind = Slice { len: len−mid }   b₂.parent = a

── Element arithmetic (p.add(k)) ──
prov(p) = (a, off)
──────────────────────────────
prov(p.add(k)) = (a, off + k·S)      S = sizeof(element)

── Byte arithmetic (p.byte_add(k)) ──
prov(p) = (a, off)
──────────────────────────────
prov(p.byte_add(k)) = (a, off + k)
```

### Alias rule

Two *live* reference views `p` and `q` alias when they name the same allocation, or sub-allocations of it:

```text
prov(p) = (a, _)    prov(q) = (b, _)
root(a) == root(b)  where root(a) follows parent(a) to the top (⊥)
```

A view is *live* when its MIR local is between its `StorageLive` and `StorageDead` (and not moved). The `parent` chain is what makes a slice view (`from_raw_parts`) or a `split_at` half count as aliasing its source, even though each has a *distinct* `AllocId` — this is why `root`, not `alloc_id` alone, is the grouping key.

## 8.5.2 Deduction Rules

The proof of a property is discharged by the following rules, using the notation declared at the top of each block:

```text
Notation:  S = sizeof_T,  A = align_T,  s : &[T],  len = s.len()
```

### Primitive properties

```text
── Slice type invariant ──
NonNull(s) ∧ Align(s, T) ∧ ValidNum(len·S ≤ isize::MAX) ∧ Allocated(s, T, len) ∧ Init(s, T, len)

── Layout ──
──────────        ──────────        ──────────────────         ────────
S ≥ 0             A ≥ 1             S % A == 0                 len ≥ 0

For a *generic* `T` (no concrete layout), `S` and `A` are the shared symbolic
constants `sizeof_T` / `align_T`.  `size_of::<T>()` / `align_of::<T>()` on such a
`T` bind to these same symbols (not `0`/`1`), so they agree with allocation
sizes and pointer strides; `align_of::<T>() ≥ 1` keeps a cast like
`align as *const T` in `NonNull::dangling` non-null.

── Allocation (s : &[T]) ──
prov(s) = (a, 0)   a.kind = Slice { len }   a.size = len·S   a.align = A   a.initialized = true

── Pointer identity ──
prov(p) = (a, off)
─────────────────────
p.term = a.base + off

── Pointer arithmetic ──
prov(p) = (a, off)                      prov(p) = (a, off)
──────────────────────────────          ──────────────────────────────
prov(p.add(k)) = (a, off + k·S)         (p.add(k)).term = p.term + k·S

── Alignment offset ──
prov(p) = (a, off)    S = sizeof(pointee)    A' = align_of::<U>()
────────────────────────────────────────────────────────────────────────────
align_offset(p, A') = k     (p.term + k·S) % A' == 0      0 ≤ k < A'

`align_offset` returns the offset in *elements* of the pointee type (not bytes),
so the aligned address is `p.term + k·S`; a downstream `p.add(k) as *const U`
then discharges `Align(p, U)`.

── Slice bound ──
prov(p) = (a, 0)    a.kind = Slice { len }
─────────────────────────────────────────
InBound(p, i) ⟺ i < len

── Byte-range case split (generic S) ──
S = 0                                          S ≥ 1
──────────────────────                        ──────────────────────
x·S = y·S = 0   (byte range vacuous)           x·S ≤ y·S ⟺ x ≤ y

── Integer arithmetic ──
i < len
─────────────
i + 1 ≤ len

── Owning (sole ownership, no double free) ──
prov(p) = (a, _)    ¬∃ live o ≠ dest : needs_drop(o) ∧ prov(o) = (a, _)
──────────────────────────────────────────────────────────────────────
Owning(p)

The check scans the *live* locals for a `needs_drop` owner whose buffer aliases
`a` (excluding the call's own destination and the reconstructed owner), which
would mean a second owner drops the same allocation.  A loop-unrolled path
(`path_facts.reenter`) and the `for_each.owning` flag (an
`Owning(container.iter())` invariant declaring every element the sole owner of
its pointee) both discharge `Owning` directly.

── Alive (liveness) ──
prov(p) = (a, _)    ¬dead(a)
────────────────────────────
Alive(p)

── Alive (assumed for a region) ──
prov(p) = (a, _)    liveness(a) = AssumedFor('a)    ¬dead(a)    'a: 'r
───────────────────────────────────────────────────────────────────────
Alive(p, 'r)

`liveness` is only consulted for external raw-pointer allocations (whose memory
is owned by the caller, so `dead` carries no guarantee). `AssumedFor('static)` is
set by a `ValidCStr(p, n)` fact, an `Allocated` raw-pointer parameter, or
`'static` const/static data; `AssumedFor('a)` by an `Alive(p, 'a)`
contract/invariant. The assumption's region must cover the demanded region
(`'a: 'r`), resolved via rustc's `FreeRegionMap` (declared `where 'a: 'b` bounds
and their transitive closure) or — for a reference parameter `&'r Self<'a>` — by
the implied outlives of the type itself (`'a: 'r`); a wider demand than the
assumption fails.

── Typed (provenance validity) ──
prov(p) = (a, _)    element_ty(a) = T   (or the slice/array element of T; MaybeUninit is vacuously typed)
─────────────────────────────────────────────────────────────────────────────────────────────────
Typed(p, T)

── Typed (pointer container) ──
prov(p) = (a, _)    for_each.target_ty(a) = T
──────────────────────────────────────────────
Typed(p, T)

── Null (guarded branch of any(Null(p), …)) ──
p.term = 0   (or p carries no non-null provenance)
───────────────────────────────────────────────────
Null(p)   (else the other disjunct decides)

── NonOverlap ──
prov(p) = (a, _)    prov(q) = (b, _)    a ≠ b
─────────────────────────────────────────────
NonOverlap(p, q, n)
(else the byte ranges [p.term, p.term+n·S) and [q.term, q.term+n·S) are disjoint — an SMT query)
```

### Layout and type-level properties

```text
── Size ──
size_of(T) = n                size_of(T) ≠ 0
──────────────────            ────────────────
Size(T, n)                    Size(T, sized)

── NoPadding ──
T has no padding bytes (scalars/pointers/refs, arrays, tuples, and non-union structs, recursively)
────────────────────────────────────────────────────────────────────────────────────────────────────
NoPadding(T)

── ValidTransmute / SplitTransmute ──
size_of(src) = size_of(dst)
───────────────────────────
ValidTransmute(src, dst)   (SplitTransmute likewise, on the element types for slices)

── Trait ──
T: Copy    (or T: Sized; or T: <trait> appears among the caller's where-clauses)
──────────────────────────────────────────────────────────────────────────────────
Trait(T, Copy)
```

### Byte-string properties

```text
── ValidString (UTF-8) ──
n = 0   ∨   the tracked bytes of prov(p)'s allocation form valid UTF-8
─────────────────────────────────────────────────────────────────────
ValidString(p, T, n)

── ValidCStr (nul-terminated) ──
nul_terminated(a)   ∨   the bytes contain no interior NUL and end with a terminal NUL
─────────────────────────────────────────────────────────────────────────────────────
ValidCStr(p, n)
```

### Compound properties

The compound safety properties are macros over the primitives (`Deref` reads "in-bounds within a live allocation"; `ValidPtr` is vacuous for a ZST, where non-nullness alone suffices):

```text
Deref(p, T, n)      = Allocated(p, T, n) ∧ InBound(p, T, n)
ValidPtr(p, T, n)   = NonNull(p) ∧ (Size(T, 0) ∨ Deref(p, T, n))
Ptr2Ref(p, T)       = Init(p, T, 1) ∧ ValidPtr(p, T, 1) ∧ Align(p, T) ∧ Alias(p)
Ptr2RefUninit(p, T) = Typed(p, T) ∧ ValidPtr(p, T, 1) ∧ Align(p, T) ∧ Alias(p)
Drop(p, T)          = ValidPtr(p, T, 1) ∧ Alias(p)
```

### Fast-path flags

The VM's derived invariants discharge the corresponding primitive without an SMT query:

```text
non_null(p)          init(p)             align_n(p) = Some(A)    in_bounds(p)   n = 1
────────────        ───────────          ─────────────────────   ────────────────────────
NonNull(p)          Init(p, T, 1)        Align(p, T)             InBound(p, T, 1)
```

These flags are *sourced*, not invented.  A raw-pointer field (`*mut T` /
`*const T` / `NonNull<T>`) carries **no** implicit `non_null`/`init`/`align`
fact: those must be declared on the struct via `#[rapx::invariant(NonNull(..))]`
/ `#[rapx::invariant(Init(..))]` / `#[rapx::invariant(Align(..))]` (or discharged
at the deref by a null guard).  A deref of an unannotated raw field therefore
fails `NonNull`/`Init` rather than silently assuming it.  A concrete `Align`
invariant is additionally recorded as the path condition `p.term % A == 0`, so it
survives pointer arithmetic (`p.add(k)`) that drops the value-level flag.

## 8.5.3 The Alias Hazard

`Alias` is a *hazard* by default — unproved `Alias` is reported as a `[hazard]` entry and contributes to `UNSOUND` — but it is also the property used to express a no-aliasing *precondition*: `Ptr2Ref(p, T)` (and `Drop(p, T)`) include `Alias(p)`, and a caller discharges the hazard by declaring `#[rapx::requires(Ptr2Ref(p, T))]`. In both roles it asserts that a reference produced by a deref does not unsafely alias other live references. It applies to any deref that produces a reference (`&*p` / `&mut *p` / `from_raw_parts`, ...); a bare `*p` read or `*p = ...` write is `Deref`/`ReadMemory`, not `Alias`.

The check runs five passes over the produced view:

```text
── Alias (hazard) ──
  applies to any deref that produces a reference (&*p / &mut *p / from_raw_parts, ...);
  a bare *p read / *p = ... write is Deref/ReadMemory, not Alias.

  The alias check runs five passes over the produced view:

  1. resolve provenance — resolve_origin(p) → the allocation p points to, and
     its origin kind: &mut → MutRef, & → SharedRef, *const/*mut → RawPtr,
     Box/Vec/NonNull → Owned.

  2. collect the live alias set (flow-sensitive) — walk the VM's *current*
     locals: a live reference view aliases p when it names the same allocation
     (provenance), or a sub-allocation of it (`from_raw_parts` / `split_at`
     keep a `parent` edge back to the allocation they were split from).

  3. callsite check — the caller's contract must discharge the raw-pointer
     provenance's aliasing:
       a `Ptr2Ref`/`Alias` precondition on p → ✓ (Alias(p) is caller-guaranteed;
         its Init/NonNull/Allocated/Align parts are separate checks)
       otherwise, shared-XOR-mutable over the live alias set (step 2):
         &*p    requires no live &mut to *p   → else ✗
         &mut *p requires no live &    to *p   → else ✗
       a raw-pointer origin without a precondition → alias set unknown, defer.

  4. forward check — while the view is live, the *origin* raw pointer must not
     be accessed again; this is also what rejects a second `&mut *p` while the
     first `&mut` is still live:
       SharedView:  a raw write through the origin → ✗
       UniqueView:  any raw access through the origin → ✗

  5. escape — is the view returned?
     not returned → the borrow ends (steps 3–4 decide).
     returned → the escape hazard must be discharged:
       an `Alias(ptr, ret)` declaration → ✓ (the caller handles the aliasing)
       a shared view from an encapsulated raw field → ✓ (a per-function
         derivation forest resolves the nested field path, e.g. `self.node.ptr`
         → `[node, ptr]`, to the innermost raw field; a private field not
         written/exposed by safe code upholds the returned `&T`)
       a shared view re-borrowed from a reference parameter → ✓ only when the
         returned region does not outlive the parameter's region (`src: ret`,
         via rustc's outlives relation); returning a `&'b str` as `&'a str`
         with `'a: 'b` is rejected.
       otherwise → ✗

  ✓ = safe   ✗ = violation   Unknown = cannot prove safe (hazard not eliminated)
```

### 8.5.3.1 Precision

The alias analysis is conservative (sound) but over-approximates:

- **Sensitive**: allocation identity (provenance `alloc_id` + `parent` chain), flow (the VM's current locals and `StorageLive`/`StorageDead` liveness), and — for the escape pass — the field path.
- **Insensitive**: byte offset/range. Two disjoint views of the same allocation (e.g. hand-written `&*p` and `&mut *p.add(1)`) are treated as aliasing. Safe-code disjoint producers (`split_at_mut`, `chunks_mut`, ...) sidestep this by modelling their halves as *separate* allocations, so they are not conflated.
- **Path/context-insensitive**: the forward scan uses CFG-reachable blocks (no path conditions), and the analysis is intra-procedural (cross-function aliasing is discharged by `Alias`/`Ptr2Ref` preconditions).

The result is no missed aliasing (sound), with false positives possible on the offset-insensitive and reference-parameter-provenance cases.
