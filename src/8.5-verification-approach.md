# Chapter 8.5. Verification Approach

The verifier discharges each safety property by symbolic reasoning over the VM state. This chapter first describes the symbolic VM state (§8.5.1), then the deduction rules that read that state (§8.5.2), and finally the special treatment of `Alias`, which is a hazard by default but also expresses a no-aliasing precondition (§8.5.3).

## 8.5.1 The Symbolic VM

### VM design

The `SymbolicVm` ([`vm/mod.rs`](https://github.com/safer-rust/RAPx/blob/main/rapx/src/verify/vm/mod.rs)) is a *semantic* MIR executor: it executes the MIR items the backward slicer retained (§8.4.2) and directly builds a symbolic state (`VmState`) with a Z3 term for every value.

Execution proceeds top-to-bottom through the diagram below. `run` allocates an empty `VmState`; `execute_items` binds the parameters to fresh symbolic values, then walks the retained items in forward path order — each MIR statement or terminator is a *transfer function* that updates the state. By the time execution reaches a checkpoint, the state reflects exactly the branch conditions and memory effects of that path.

```text
   ProofGoal { path, items: Vec<RelevantItem>, block_fn }
   (produced by the backward slicer, §8.4.2)
                    │
                    ▼
   SymbolicVm::run(z3_ctx, tcx, goal)        ← stateless, pure input → state
                    │
                    ▼
   VmState::new(...)                      ← empty state (structure below)
                    │
                    ▼
   execute_items(&items)                  ← forward path order
                    │
                    ├─ init_parameters():  _1.._N ← fresh Z3 constants
                    │
                    └─ for item in items:
                          Statement    → exec_statement
                          Terminator   → exec_terminator
                          CalleeEntry  → handle_callee_entry  (save_frame)
                          CalleeExit   → handle_callee_exit   (restore_frame)
                          ContractFact → assert_contract_fact
                          UnknownCall  → (no-op)
                     ▼
   VmState ──► PropertyChecker::check ──► Z3 (assert_all + negation-as-failure)
```

The `SymbolicVm` takes the MIR of each path as input and maintains the following state during execution (besides the borrowed `z3_ctx`/`tcx` handles):

- **Frame-scoped** (`current_frame: FrameState`) — saved/restored on inline entry/exit, so a callee reuses MIR locals freely:
  - `current_def_id` — the function whose body is being executed.
  - `local_alloc` — the stack allocation backing each local's place.  This is the *only* name → object binding: a local's whole value lives at `path == []` and its field values at `path == [i, ..]` in the path-scoped `Memory::values` (keyed by the local's allocation and declared type), so there is no local-keyed value table here.

- **Path-scoped** (everything else) — accumulates across the whole path, including inlined frames:
  - `memory` — the object space: `allocations`, per-byte `byte_arrays`/`byte_max`, and the typed-value layer `values` (whole values at `path == []` and field values at `path == [i, ..]`).
  - `constraints` — accumulated solver `assertions` and the term `term_caches`.
  - `caller_frames` — saved caller frames for path-replay inlining.
  - `inline` — recursive-inline scratch: `inline_depth`, `arg_referents`, `deferred_field_writes`.
  - `path_facts` — per-path facts: `reenter`, `alias_hazard_accepted`, `has_checked_bounds`, ….

The deduction rules in §8.5.2 read three things out of this state — values, allocations, and provenance — described in the subsections below.

### Values and invariants

A MIR local's whole value (its rvalue) and each of its field values are both symbolic values (`VmValue`), stored in `Memory::values` keyed by `(alloc, view_ty, path)` — `path == []` is the whole value, `path == [i, ..]` is field `i` (viewed as `view_ty`, so a reinterpret cast resolves to the right field view):

```text
VmValue { z3_term, ty, provenance, invariants, source }
```

- `z3_term` — a Z3 term. For pointer/reference types (`&T`, `*const T`, `Box<T>`, …) it is the address; for scalar types it is the value; for aggregate types it is the base address of the stack slot backing the aggregate.
- `ty` — the Rust type, for layout queries.
- `provenance` — `Option<Provenance>` (see below); `None` for a scalar.
- `invariants` — the derived invariants (`ValueInvariants`) that serve as the "fast-path flags" of §8.5.2:
  - `non_null: bool`, `init: bool`, `in_bounds: bool`.
  - `align_n: Option<Int>` — the pointer's *alignment lower bound*. Here `Int` is `z3::ast::Int`, a **Z3 term**, not a Rust integer: `Some(n)` asserts `z3_term % n == 0`, i.e. the pointer is at least `n`-aligned (alignments are powers of two, so "at least `n`" ⇔ "a multiple of `n`"). For a *concrete* type `n` is a constant term (`Some(8)`); for a *generic* type `n` is the *symbolic* constant `align_T` — a fresh Z3 constant shared per type — so a generic `T` is carried as a symbol, not a number. `None` records **no** alignment fact (e.g. a raw pointer `*mut T`), independent of whether `T` is generic.
- `source` — a `ValueSource` carrying any extra semantics beyond z3_term/type/provenance:
  - `None` — a plain value.
  - `FieldOffset` — a compile-time `offset_of!` field offset, propagated to a pointer's provenance when used as an `add`/`byte_add` offset.
  - `Discriminant(Int)` — a symbolic enum variant index (e.g. `Iterator::next` returns `Some(x)` iff `!is_empty`), tying `switchInt` branches to the real condition instead of a fresh symbol.
  - `Comparison { lhs, rhs, op, cond }` — a comparison result (`Le`/`Lt`/`Ge`/`Gt`/`Eq`/`Ne`): the operands plus the direct boolean condition (`offset <= len`), so `switchInt`/`Assert` emit a precise path condition instead of `ite(cond, 1, 0) != 0`.
  - `BinaryOp { lhs, rhs, op }` — a non-comparison binary-op result (`Add`/`Sub`/…/`Div`/`Rem`), used for guard inference (tracing a switch/assert guard back to the pointer it null-checks/alignment-checks) and division-axiom injection.

### Allocation table

Every allocation `a` the VM tracks is one entry in an allocation table (`vm::state::Allocation`, stored at `Memory::allocations[a]`). Its fields, grouped as in the code:

- **Shape** (always present):
  - `base: Int` — base address (a fresh Z3 constant).
  - `size: Int` — byte size (may be symbolic; an external parameter is sized as "unbounded").
  - `align: Int` — alignment in bytes (may be symbolic for a generic element type).
  - `element_ty: ContentTy` — the contents' type: `Typed(T)` for a concrete `Ty` (or `u8` for a raw byte buffer), or `Generic` for a symbolic `T`.
  - `kind: AllocKind` — `Object` (a single `Box<T>`/struct/scalar/untyped buffer), `Slice { len }` (a slice/array buffer, with `size == len · size_of(element_ty)`), or `External` (an external raw-pointer parameter of unknown size/nullability — nullability is tracked on the pointer term, not here).
- **Facts** (`facts: AllocFacts`) — cross-cutting per-allocation facts, kept apart from the shape metadata above:
  - `dead: bool` — freed (`StorageDead`/`Drop`).
  - `initialized: bool` — contents hold a readable value (`Box::new`/`Vec`/reference referent/callee return/write/`ValidCStr`/const data); `false` for `new_uninit`/`uninit`.
  - `liveness: Option<Region>` — the region an *external* allocation is assumed alive for (`Alive(p, 'a)` contract / `'static`); only consulted for external allocations, whose memory is caller-owned (so `dead` carries no guarantee). `None` = no assumption.
  - `cstr_trusted: bool` — a null-terminated byte buffer (valid C string).
  - `for_each: ForEachFacts` — uniform facts about the container's *pointer elements* (`x.iter()` for_each invariants), anchored to the allocation so a pointer loaded from it resolves the fact via its provenance: `target_ty` (Typed), `aligned_ty` (Align), `allocated: (Ty, n)` (Allocated, `n` may be symbolic), `owning` (Owning).
- **Relationships** (optional):
  - `parent: Option<AllocId>` — the source allocation of a sub-view (`s[i..j]`/`get`/`split_at`/`align_to`/`as_chunks`/`from_raw_parts`); `root_alloc` follows this edge to group aliasing views.

The data allocation of a two-part value (`Vec`/`String`/`CString`) is **not** stored as an edge: it is re-derived on demand from the header's *owning pointer field* — the field whose provenance names the heap buffer, located generically by `container_ptr_field` (`Box.0.pointer` → `[0, 0]`, `Vec.buf.ptr.pointer` → `[0, 0, 0]`). `data_alloc_of` reads that field's provenance; for a slice view whose header `AllocId` no longer carries a type key it falls back to `header_data_alloc` (scan the header's materialized fields for the single owning-pointer provenance). A `&[T]` reference needs neither — its provenance already names the data.

The entry differs by how the allocation was created:

| creation | kind | element_ty | parent |
|---|---|---|---|
| `Box::new(v)` — heap object | `Object` | `Typed(T)` | — |
| `Vec`'s heap buffer | `Slice { len }` | `Typed(T)` | — |
| `&[T]` reference's stack slot | `Object` | `Typed(T)` | — |
| `split_at` half / `from_raw_parts` view | `Slice { mid }` | `Typed(T)` | `Some(src)` |
| external `*mut T` parameter | `External` | `Typed(T)` | — |

### Provenance

Every pointer value carries the allocation it points into, the byte offset within it, and (when known) the structure of that offset:

```text
provenance(p) = { alloc_id: a, offset: off, offset_kind: k }   ⇔   p points into allocation a at byte offset off
```

`offset_kind` classifies the offset so the checker can use a cheaper, more precise proof: `Field` carries the "field in-bounds" guarantee (`offset + size_of(field) <= size_of(container)`, e.g. `Option::as_slice`); `Element(i)` tracks the element index so `InBound` checks `i + count <= slice_len` linearly instead of the non-linear byte form `(i+count)·S <= len·S` (undecidable in Z3 NIA for a generic `S`); `Byte` marks a byte-strided (`byte_add`) or unclassifiable offset. `offset_kind` is `None` at the base (`offset == 0`).

A cast (`&mut → *mut`, `*mut → *const`) preserves provenance; a plain copy `q = p` copies provenance (so `p` and `q` are aliases).

### Provenance recording rules

The VM maintains provenance in execution order, one transfer per MIR statement/terminator. Below, `prov(p) = (a, off)` abbreviates the full `provenance(p) = { alloc_id: a, offset: off, offset_kind }`, and `slice_len` denotes `AllocKind::Slice { len }` (read via `Allocation::slice_len()`):

```text
── Allocation creation (Box::new / Vec::new / …) ──
a := fresh
──────────────────────────────────────────
prov(p) = (a, 0)      a.parent = ⊥         (a.kind = Slice { len } for a Vec/slice)

── View of a pointer (&*p / &mut *p / as_ptr / as_mut_ptr / into_raw) ──
prov(p) = (a, off)
────────────────────────
prov(&*p) = prov(p) = (a, off)          (the view inherits p's provenance)

── Slice view (from_raw_parts(ptr, n)) ──
prov(ptr) = (a, off)
────────────────────────────────────────
b := fresh   prov(s) = (b, 0)   b.kind = Slice { len: n }   b.parent = a

── Split (split_at(s, mid)) ──
prov(s) = (a, 0)   a.kind = Slice { len }   0 ≤ mid ≤ len
──────────────────────────────────────────────────────────────
prov(s[..mid]) = (b₁, 0)   b₁.kind = Slice { len: mid }      b₁.parent = a
prov(s[mid..]) = (b₂, 0)   b₂.kind = Slice { len: len−mid }   b₂.parent = a

── Element arithmetic (p.add(k)) ──
prov(p) = (a, off)
──────────────────────────────
prov(p.add(k)) = (a, off + k·S)      S = sizeof(element)

── Byte arithmetic (p.byte_add(k)) ──
prov(p) = (a, off)
──────────────────────────────
prov(p.byte_add(k)) = (a, off + k)

── Cast reinterprets a buffer (byte ↔ field) ──
A `*mut u8` ↔ `*mut T` cast switches the *view* of an allocation without
changing its bytes.  A *scalar* field round-trips across the two views
(little-endian, concrete size); a *pointer* field does not — provenance is not a
byte, so a byte→field read of a pointer field mints a fresh symbol:

  byte → field:  field(i).z3_term = Σⱼ byte[off(i) + j] · 256ʲ
  field → byte:  byte[off(i) + j]  = (field(i).z3_term ÷ 256ʲ) mod 256

where `off(i)` is field `i`'s byte offset and `256ʲ` is its byte-weight.
```

### Alias rule

Two *live* reference views `p` and `q` alias when they name the same allocation, or sub-allocations of it:

```text
prov(p) = (a, _)    prov(q) = (b, _)
root(a) == root(b)  where root(a) follows parent(a) to the top (⊥)
```

A view is *live* when its MIR local is between its `StorageLive` and `StorageDead` (and not moved). The `parent` chain is what makes a slice view (`from_raw_parts`) or a `split_at` half count as aliasing its source, even though each has a *distinct* `AllocId` — this is why `root`, not `alloc_id` alone, is the grouping key.

## 8.5.2 Deduction Rules

The proof of a property combines two kinds of rule. **State-construction axioms** describe how the symbolic VM builds the state — model invariants, not obligations. **Property discharge rules** prove each primitive from that state, through a *fast path* (a derived flag or layout fact, no solver) or an *SMT query* (the accumulated constraints plus the negation of the goal). Compound properties are macros over the primitives, and the fast-path flags shortcut the same rules without a query. Notation used throughout:

```text
Notation:  S = sizeof_T,  A = align_T,  s : &[T],  len = s.len()
```

### State-construction axioms

These hold by construction of the symbolic VM — each transfer function records how it updates `VmState`; none is a property the checker proves.

```text
── Slice type invariant ──
NonNull(s) ∧ Align(s, T) ∧ ValidNum(len·S ≤ isize::MAX) ∧ Allocated(s, T, len) ∧ Init(s, T, len)

── Layout ──
──────────        ──────────        ──────────────────         ────────
S ≥ 0             A ≥ 1             S % A == 0                 len ≥ 0

For a *generic* `T` (no concrete layout), `S` and `A` are the shared symbolic
constants `sizeof_T` / `align_T`.  `size_of::<T>()` / `align_of::<T>()` on such a
`T` bind to these same symbols (not `0`/`1`), so they agree with allocation
sizes and pointer strides; `align_of::<T>() ≥ 1` keeps a cast like
`align as *const T` in `NonNull::dangling` non-null.

── Allocation (s : &[T]) ──
prov(s) = (a, 0)   a.kind = Slice { len }   a.size = len·S   a.align = A   a.initialized = true

── Pointer identity ──
prov(p) = (a, off)
─────────────────────
p.z3_term = a.base + off

── Pointer arithmetic ──
prov(p) = (a, off)                      prov(p) = (a, off)
──────────────────────────────          ──────────────────────────────
prov(p.add(k)) = (a, off + k·S)         (p.add(k)).z3_term = p.z3_term + k·S

── Alignment offset ──
prov(p) = (a, off)    S = sizeof(pointee)    A' = align_of::<U>()
────────────────────────────────────────────────────────────────────────────
align_offset(p, A') = k     (p.z3_term + k·S) % A' == 0      0 ≤ k < A'

`align_offset` is modelled as returning the offset in *elements* of the pointee
type (not bytes), so the aligned address is `p.z3_term + k·S`; a downstream
`p.add(k) as *const U` then discharges `Align(p, U)`.  The bound `k < A'` is a
loose (sound) upper bound — the exact element bound is `A' / S`.

── Byte-range case split (generic S) ──
S = 0                                          S ≥ 1
──────────────────────                        ──────────────────────
x·S = y·S = 0   (byte range vacuous)           x·S ≤ y·S ⟺ x ≤ y

── Integer arithmetic ──
i < len
─────────────
i + 1 ≤ len
```

### Memory-shape properties

Each rule proves one memory-shape primitive from the state built above. Fast paths use the derived flags and layout facts of §8.5.1; otherwise an SMT query asserts the constraints plus the negation of the goal.

```text
── Align(p, T) ──
p.z3_term % align_of(T) == 0
────────────────────────────
Align(p, T)

Fast paths (no query): `align_of(T) == 1` or `T` a concrete ZST (aligned by
definition); `align_n(p) ≥ align_of(T)` — compared structurally when both terms
are concrete powers of two, and by a linear SMT query when `align_of(T)` is a
symbolic `align_T` (for a generic `T`, `align_n` and `align_of(T)` are the *same*
shared `align_T` constant, so `align_T ≥ align_T` is trivially discharged);
`align_n` is only a *lower bound* on `p`'s alignment, so it discharges
`Align(p, T)` only when it is at least `align_of(T)`, never below; a
`for_each.aligned_ty(a) = U` fact with `align_of(U) ≥ align_of(T)`; a stack
borrow of a local whose type alignment is `≥ align_of(T)`; an allocation base
with `align(a) ≥ align_of(T)` and `off % align_of(T) == 0`.  Otherwise an SMT
modulo query under `p.z3_term = a.base + off` and `a.base % align(a) == 0`.

── NonNull(p) ──
non_null(p)   ∨   (prov(p) = (a, _) ∧ ¬external(a))   ∨   p.z3_term ≠ 0 (SMT)
───────────────────────────────────────────────────────────────────────────────
NonNull(p)

A tracked stack/heap allocation's base is never zero, so `¬external` implies
non-null; an *external* raw-pointer allocation carries no implied non-nullness
and is discharged only by a `#[rapx::invariant(NonNull(..))]`-derived
`non_null` flag or by proving `p.z3_term ≠ 0` from the path conditions.

── Allocated(p, T, n) ──
prov(p) = (a, off)    ¬dead(a)    off + n·S ≤ size(a)
──────────────────────────────────────────────────────
Allocated(p, T, n)

Vacuous when `n == 0` (any pointer is valid for its 0-byte prefix).  A type
compatibility fast path (element type matches `T`, `MaybeUninit<T>` ≡ `T`,
array/slice element, or a smart-pointer peel) discharges without the byte-range
query; an external "unbounded" allocation (sized `i64::MAX`) auto-passes; a
field-offset pointer checks against the *field's* size.

── InBound(p, T, n) ──
prov(p) = (a, off)    off = k·S (element stride)    a.kind = Slice { len }
────────────────────────────────────────────────────────────────────────────
InBound(p, T, n)  ⟺  k + n ≤ len

The slice form `InBound(s, i)` is the base case (`k = 0, n = 1`): `i < len` (for
a range index, `end ≤ len`).  Without an element-strided offset the check falls
back to the byte form `off + n·S ≤ size(a)` (case-split on `S` for a generic
element size).  Vacuous when `n == 0`; a ZST auto-passes; a field-offset pointer
checks against the field's own size.

── Init(p, T, n) ──
prov(p) = (a, off)    ∀ b ∈ [off, off + n·S) : initialized(a, b)
────────────────────────────────────────────────────────────────────
Init(p, T, n)

Vacuous when `n == 0`.  `Init(p, MaybeUninit<T>, n)` reduces to `Typed` —
`MaybeUninit<T>` carries no validity invariant, so there is nothing to
initialize.  Byte-level coverage is decided by the allocation's `initialized`
flag / per-byte `byte_arrays` (`byte[i] = select(array, i)`, unwritten offsets read the `UNINIT` sentinel); a byte never written is a confirmed violation.

── Owning(p) ──
prov(p) = (a, _)    ¬∃ live o ≠ dest : needs_drop(o) ∧ prov(o) = (a, _)
──────────────────────────────────────────────────────────────────────
Owning(p)

The check scans the *live* locals for a `needs_drop` owner whose buffer aliases
`a` (excluding the call's own destination and the reconstructed owner), which
would mean a second owner drops the same allocation.  A loop-unrolled path
(`path_facts.reenter`) and the `for_each.owning` flag (an
`Owning(container.iter())` invariant declaring every element the sole owner of
its pointee) both discharge `Owning` directly.

── Alive(p) ──
prov(p) = (a, _)    ¬dead(a)    (a is a tracked allocation, or p is a live reference/owner)
────────────────────────────
Alive(p)

── Alive (assumed for a region) ──
prov(p) = (a, _)    liveness(a) = Some('a)    ¬dead(a)    'a: 'r
───────────────────────────────────────────────────────────────────────
Alive(p, 'r)

`liveness` is only consulted for external raw-pointer allocations (whose memory
is owned by the caller, so `dead` carries no guarantee). `Some('static)` is
set by a `ValidCStr(p, n)` fact, an `Allocated` raw-pointer parameter, or
`'static` const/static data; `Some('a)` by an `Alive(p, 'a)`
contract/invariant. The assumption's region must cover the demanded region
(`'a: 'r`), resolved via rustc's `FreeRegionMap` (declared `where 'a: 'b` bounds
and their transitive closure) or — for a reference parameter `&'r Self<'a>` — by
the implied outlives of the type itself (`'a: 'r`); a wider demand than the
assumption fails.

── Typed(p, T) ──
prov(p) = (a, _)    element_ty(a) = T   (or a field of `T` at `off`; MaybeUninit is vacuously typed)
─────────────────────────────────────────────────────────────────────────────────────────────────
Typed(p, T)

── Typed (pointer container) ──
prov(p) = (a, _)    for_each.target_ty(a) = T
──────────────────────────────────────────────
Typed(p, T)

── Null (guarded branch of any(Null(p), …)) ──
p.z3_term = 0   (or p carries no non-null provenance)
───────────────────────────────────────────────────
Null(p)   (else the other disjunct decides)

── NonOverlap(p, q, n) ──
prov(p) = (a, _)    prov(q) = (b, _)    a ≠ b
─────────────────────────────────────────────
NonOverlap(p, q, n)
(else the byte ranges [p.z3_term, p.z3_term+n·S) and [q.z3_term, q.z3_term+n·S) are disjoint — an SMT query)

Two pointers into the *same* allocation at disjoint ranges fall through to the
byte-range query.  Note a precision gap: the fast path keys on raw `alloc_id`,
not the `root`-based alias grouping, so two sub-views of one allocation with
distinct ids but overlapping byte ranges are accepted without the byte-range
check.
```

### Layout and type-level properties

```text
── Size ──
size_of(T) = n                T: Sized ∧ size_of(T) > 0
──────────────────            ───────────────────────────
Size(T, n)                    Size(T, sized)

── NoPadding ──
T has no padding bytes (scalars/pointers/refs, arrays, tuples, and non-union structs, recursively)
────────────────────────────────────────────────────────────────────────────────────────────────────
NoPadding(T)

── ValidTransmute ──
size_of(src) = size_of(dst)     (a generic size — `0` — trusts the type system, since the call compiled)
──────────────────────────────────────────────────────────────────────────────────────────────────────
ValidTransmute(src, dst)

── SplitTransmute ──
src_elem = dst_elem   ∨   dst_elem is SIMD with a src lane   ∨   all-bit-patterns-valid(dst_elem)
──────────────────────────────────────────────────────────────────────────────────────────────────────
SplitTransmute([Src], [Dst])

── Trait ──
T: Copy    (or T: Sized; or T: <trait> appears among the caller's where-clauses)
──────────────────────────────────────────────────────────────────────────────────
Trait(T, Copy)
```

### Numeric and byte-string properties

```text
── ValidNum ──
∀ pred :  assert_all ∧ ¬cond(pred) is UNSAT    (with Euclidean-division/NIA axioms)
─────────────────────────────────────────────────────────────────────────────
ValidNum(...)

Each predicate (`index < len`, or the interval form desugared to `lo ≤ v ∧ v ≤ hi`)
is evaluated to a Z3 comparison; the negation is shown unsatisfiable under the path
constraints, with division axioms (`X = (X/N)·N + X%N`) injected to decide non-linear
inequalities.  A `size_of::<T>() · count ≤ isize::MAX`-shaped predicate (the slice
size invariant) is discharged by rule without a query.

── ValidString (UTF-8) ──
n = 0   ∨   the tracked bytes of prov(p)'s allocation form valid UTF-8
─────────────────────────────────────────────────────────────────────
ValidString(p, T, n)

── ValidCStr (nul-terminated) ──
cstr_trusted(a)   ∨   the bytes contain no interior NUL and end with a terminal NUL
─────────────────────────────────────────────────────────────────────────────────────
ValidCStr(p, n)
```

### Compound properties

The compound safety properties are macros over the primitives (`Deref` reads "in-bounds within a live allocation"; `ValidPtr` is vacuous for a ZST, where non-nullness alone suffices):

```text
Deref(p, T, n)      = Allocated(p, T, n) ∧ InBound(p, T, n)
ValidPtr(p, T, n)   = NonNull(p) ∧ (Size(T, 0) ∨ Deref(p, T, n))
Ptr2Ref(p, T)       = Init(p, T, 1) ∧ ValidPtr(p, T, 1) ∧ Align(p, T) ∧ Alias(p)
Ptr2RefUninit(p, T) = Typed(p, T) ∧ ValidPtr(p, T, 1) ∧ Align(p, T) ∧ Alias(p)
Drop(p, T)          = ValidPtr(p, T, 1) ∧ Alias(p)
```

### Fast-path flags

The VM's derived value invariants shortcut three primitives without an SMT query:

```text
non_null(p)          in_bounds(p)          align_n(p) ≥ align_of(T)      (both powers of two)
────────────        ─────────────────      ────────────────────────────
NonNull(p)          InBound(p, T, 1)       Align(p, T)
```

`non_null` proves `NonNull`; `in_bounds` proves `InBound(p, T, 1)` (a single-element bound, established by a prior deref or contract); `align_n` is a *lower bound* on `p`'s alignment, so it proves `Align(p, T)` only when it is at least `align_of(T)`.  The value's `init` flag is *not* a shortcut for `Init(p, T, 1)`: `Init` concerns the *pointee memory's* initialized bytes (the allocation's `initialized` flag / per-byte `byte_arrays`), whereas `init` marks a *value* whose content is known initialized — it feeds the `Typed` fast paths and the `MaybeUninit` write exceptions, not the `Init` check.

These flags are *sourced*, not invented.  A raw-pointer field (`*mut T` /
`*const T` / `NonNull<T>`) carries **no** implicit `non_null`/`init`/`align`
fact: those must be declared on the struct via `#[rapx::invariant(NonNull(..))]`
/ `#[rapx::invariant(Init(..))]` / `#[rapx::invariant(Align(..))]` (or discharged
at the deref by a null guard).  A deref of an unannotated raw field therefore
fails `NonNull`/`Init` rather than silently assuming it.  A concrete `Align`
invariant is additionally recorded as the path condition `p.z3_term % A == 0`, so it
survives pointer arithmetic (`p.add(k)`) that drops the value-level flag.

## 8.5.3 The Alias Hazard

`Alias` is a *hazard* by default — unproved `Alias` is reported as a `[hazard]` entry and contributes to `UNSOUND` — but it is also the property used to express a no-aliasing *precondition*: `Ptr2Ref(p, T)` (and `Drop(p, T)`) include `Alias(p)`, and a caller discharges the hazard by declaring `#[rapx::requires(Ptr2Ref(p, T))]`. In both roles it asserts that a reference produced by a deref does not unsafely alias other live references. It applies to any deref that produces a reference (`&*p` / `&mut *p` / `from_raw_parts`, ...); a bare `*p` read or `*p = ...` write is `Deref`/`ReadMemory`, not `Alias`.

The check runs five passes over the produced view:

```text
── Alias (hazard) ──
  applies to any deref that produces a reference (&*p / &mut *p / from_raw_parts, ...);
  a bare *p read / *p = ... write is Deref/ReadMemory, not Alias.

  The alias check runs five passes over the produced view:

  1. resolve provenance — resolve_origin(p) → the allocation p points to, and
     its origin kind: &mut → MutRef, & → SharedRef, *const/*mut → RawPtr,
     Box/Vec/NonNull → Owned.

  2. collect the live alias set (flow-sensitive) — walk the VM's *current*
     locals: a live reference view aliases p when it names the same allocation
     (provenance), or a sub-allocation of it (`from_raw_parts` / `split_at`
     keep a `parent` edge back to the allocation they were split from).

  3. callsite check — the caller's contract must discharge the raw-pointer
     provenance's aliasing:
       a `Ptr2Ref`/`Alias` precondition on p → ✓ (Alias(p) is caller-guaranteed;
         its Init/NonNull/Allocated/Align parts are separate checks)
       otherwise, shared-XOR-mutable over the live alias set (step 2):
         &*p    requires no live &mut to *p   → else ✗
         &mut *p requires no live &    to *p   → else ✗
       a raw-pointer origin without a precondition → alias set unknown, defer.

  4. forward check — while the view is live, the *origin* raw pointer must not
     be accessed again; this is also what rejects a second `&mut *p` while the
     first `&mut` is still live:
       SharedView:  a raw write through the origin → ✗
       UniqueView:  any raw access through the origin → ✗

  5. escape — is the view returned?
     not returned → the borrow ends (steps 3–4 decide).
     returned → the escape hazard must be discharged:
       an `Alias(ptr, ret)` declaration → ✓ (the caller handles the aliasing)
       a shared view from an encapsulated raw field → ✓ (a per-function
         derivation forest resolves the nested field path, e.g. `self.node.ptr`
         → `[node, ptr]`, to the innermost raw field; a private field not
         written/exposed by safe code upholds the returned `&T`)
       a shared view re-borrowed from a reference parameter → ✓ only when the
         returned region does not outlive the parameter's region (`src: ret`,
         via rustc's outlives relation); returning a `&'b str` as `&'a str`
         with `'a: 'b` is rejected.
       otherwise → ✗

  ✓ = safe   ✗ = violation   Unknown = cannot prove safe (hazard not eliminated)
```

### 8.5.3.1 Precision

The alias analysis is conservative (sound) but over-approximates:

- **Sensitive**: allocation identity (provenance `alloc_id` + `parent` chain), flow (the VM's current locals and `StorageLive`/`StorageDead` liveness), and — for the escape pass — the field path.
- **Insensitive**: byte offset/range. Two disjoint views of the same allocation (e.g. hand-written `&*p` and `&mut *p.add(1)`) are treated as aliasing. Safe-code disjoint producers (`split_at_mut`, `chunks_mut`, ...) sidestep this by modelling their halves as *separate* allocations, so they are not conflated.
- **Path/context-insensitive**: the forward scan uses CFG-reachable blocks (no path conditions), and the analysis is intra-procedural (cross-function aliasing is discharged by `Alias`/`Ptr2Ref` preconditions).

The result is no missed aliasing (sound), with false positives possible on the offset-insensitive and reference-parameter-provenance cases.
